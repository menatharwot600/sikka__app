## 1. نظرة عامة

**سكة** أبليكيشن طلبات بسيط بيربط بين نوعين من المستخدمين:

- **العميل**: بيكتب أوردره (أي حاجة عايزها) ويستنى حد يجيبله ويوصله.
- **الدليفري (المُوصِّل)**: بيشوف الأوردرات المتاحة، بياخد اللي يقدر عليه، ويوصله للعميل.

المرحلة الحالية: **نسخة متكاملة (Full version)**، مبنية كـ **PWA** (تطبيق ويب يتصرف زي أبليكيشن موبايل حقيقي) — مجاني بالكامل في البناء والاستضافة، وشغال فوراً على أندرويد وآيفون من غير الحاجة لمتاجر التطبيقات.

---

## 2. المستخدمين والأدوار

| الدور | يقدر يعمل ايه |
|---|---|
| **عميل** | يسجل حساب، يكتب أوردر جديد (وصف + مكان تسليم + رقم تليفون)، يتابع حالة كل أوردر بعتها |
| **دليفري** | يسجل حساب، يشوف قائمة الأوردرات المتاحة (اللي محدش أخدها)، ياخد أوردر واحد بس في المرة، يحدّث حالته لحد التسليم |

**تسجيل الدخول موحّد**: نفس الرابط لكل المستخدمين، وبيحددوا دورهم (عميل / دليفري) وقت التسجيل، والنظام بيوجههم للشاشة المناسبة تلقائياً.

---

## 3. الفلو الأساسي (User Flow)

```
العميل                                    الدليفري
──────                                    ────────
يسجل / يدخل                               يسجل / يدخل
   │                                          │
يكتب أوردر جديد                            يشوف قائمة الأوردرات
(وصف + مكان + تليفون)                       المتاحة (جديدة فقط)
   │                                          │
الأوردر يظهر "جديد"                        يدوس "خد الأوردر"
   │                                          │
                                          الأوردر بقى "مأخوذ"
                                          (مقفول على باقي الدليفريز)
                                              │
                                          يحدّث الحالة: في الطريق
   │                                          │
العميل بيشوف الحالة                       يوصل الأوردر
تتحدث لايف (Real-time)                    يحدّث الحالة: تم التسليم
                                              │
                                          يقدر ياخد أوردر جديد تاني
```

## 4. القواعد المنطقية (Business Rules)

- الدليفري بياخد **أوردر واحد بس** في نفس الوقت — مينفعش ياخد أوردر جديد لحد ما يخلّص اللي معاه (يوصله أو يلغيه).
- أول دليفري يدوس "خد الأوردر" هو اللي بياخده — بمجرد ما يتاخد، بيختفي من قائمة "الأوردرات المتاحة" عند باقي الدليفريز.
- العميل يقدر يشوف كل أوردراته (الحالية والسابقة) وحالة كل واحد فيهم لحظة بلحظة.
- تحديثات الحالة بتحصل **Real-time** (من غير ما حد يعمل تحديث/Refresh يدوي للصفحة).

## 5. حالات الأوردر (Order Status)

| الحالة | معناها |
|---|---|
| 🟡 **جديد** | الأوردر اتبعت ولسه محدش أخده |
| 🔵 **مأخوذ** | دليفري معين خده وهيجهزه |
| 🟣 **في الطريق** | الدليفري في طريقه للعميل |
| 🟢 **تم التسليم** | الأوردر وصل بنجاح |
| 🔴 **ملغي** | اتلغى (من العميل أو الدليفري) قبل التسليم |

## 6. الشاشات (Screens)

### أ. شاشة تسجيل الدخول / التسجيل
- اختيار الدور: عميل أو دليفري
- حقول التسجيل: الاسم، رقم التليفون، الإيميل، كلمة السر
- رابط للتبديل بين "تسجيل دخول" و"حساب جديد"

### ب. شاشة العميل (الرئيسية)
- كارت "اطلب دلوقتي": وصف حر للأوردر + مكان التسليم + رقم التليفون + زرار "ابعت الأوردر"
- قائمة "أوردراتي": كل أوردر بحالته الحالية، بترتيب الأحدث أولاً

### ج. شاشة الدليفري
- قائمة الأوردرات المتاحة (اللي حالتها "جديد")
- زرار "خد الأوردر" على كل أوردر
- شاشة "أوردري الحالي" مع أزرار تحديث الحالة (في الطريق / تم التسليم / إلغاء)

> الحالة: الشاشتين (أ) و(ب) و(ج) دلوقتي متوصلة فعلياً بـ Supabase (مش Mock data) — قراءة وكتابة حقيقية + Realtime.

## 8. قاعدة البيانات (Database Schema — Supabase / PostgreSQL)

### جدول `profiles`
| العمود | النوع | الوصف |
|---|---|---|
| `id` | uuid (PK, من Supabase Auth) | معرف اليوزر |
| `full_name` | text | اسم اليوزر |
| `phone` | text | رقم التليفون |
| `role` | text (`customer` / `courier`) | دور اليوزر |
| `created_at` | timestamp | تاريخ التسجيل |

### جدول `orders`
| العمود | النوع | الوصف |
|---|---|---|
| `id` | uuid (PK) | معرف الأوردر |
| `customer_id` | uuid (FK → profiles) | صاحب الأوردر |
| `courier_id` | uuid (FK → profiles, nullable) | الدليفري اللي أخده (فاضي لحد ما يتاخد) |
| `description` | text | وصف الأوردر |
| `delivery_location` | text | مكان التسليم |
| `phone` | text | رقم تليفون التواصل |
| `status` | text | `new` / `claimed` / `on_the_way` / `delivered` / `cancelled` |
| `created_at` | timestamp | وقت إنشاء الأوردر |
| `updated_at` | timestamp | آخر تحديث لحالته |

**قاعدة أمان (RLS) أساسية:**
- العميل يشوف ويعدّل أوردراته هو بس.
- الدليفري يشوف كل الأوردرات "الجديدة" + الأوردر اللي هو خده.
- تحديث `courier_id` و `status` من "جديد" لـ "مأخوذ" مسموح بس لو الأوردر لسه "جديد" (يمنع اتنين دليفري ياخدوا نفس الأوردر في نفس اللحظة).

## 9. التقنيات المستخدمة (Tech Stack)

| الطبقة | الأداة | السبب |
|---|---|---|
| **الواجهة (Frontend)** | React + Vite | سريع، خفيف، وسهل يتحول لـ PWA |
| **التصميم** | Tailwind CSS | بناء سريع ومتسق للواجهات |
| **قاعدة البيانات + Auth + Real-time** | Supabase (PostgreSQL) | مجاني، بيدي تسجيل دخول وقاعدة بيانات لايف من غير سيرفر منفصل |
| **PWA** | vite-plugin-pwa | تحويل الأبليكيشن لحاجة تتثبت على الموبايل زي أبليكيشن حقيقي |
| **الاستضافة** | Vercel / Netlify (مجاني) | نشر الأبليكيشن على رابط حقيقي |
